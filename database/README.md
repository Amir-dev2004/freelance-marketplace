# مستندات پایگاه داده پروژه پلتفرم فریلنسری

## ۱. معرفی

پایگاه داده پروژه پلتفرم فریلنسری با استفاده از **Microsoft SQL Server** طراحی و پیاده‌سازی شده و مدیریت آن از طریق نرم‌افزار **SQL Server Management Studio (SSMS)** انجام می‌شود.

هدف این پایگاه داده، مدیریت کاربران، پروژه‌ها، پیشنهادهای همکاری، مهارت‌ها، دسته‌بندی‌ها، اطلاعات حرفه‌ای کاربران، نمونه‌کارها و گواهینامه‌ها است.

## ۲. ساختار جداول

پایگاه داده شامل ۱۲ جدول اصلی است:

| نام جدول | کاربرد |
|---|---|
| `User` | ذخیره اطلاعات حساب کاربران |
| `AdminAccounts` | مشخص کردن حساب‌های مدیر سیستم |
| `Project` | ذخیره اطلاعات پروژه‌های ثبت‌شده |
| `proposal` | ذخیره پیشنهادهای فریلنسرها برای پروژه‌ها |
| `Categories` | نگهداری دسته‌بندی پروژه‌ها |
| `Skills` | نگهداری مهارت‌های قابل انتخاب |
| `ProjectCategories` | ارتباط پروژه‌ها با دسته‌بندی‌ها |
| `ProjectSkills` | ارتباط پروژه‌ها با مهارت‌های موردنیاز |
| `UserSkills` | ارتباط کاربران با مهارت‌هایشان |
| `UserProfiles` | ذخیره اطلاعات تکمیلی و حرفه‌ای کاربران |
| `PortfolioItems` | نگهداری نمونه‌کارهای کاربران |
| `Certificates` | نگهداری گواهینامه‌های کاربران |

## ۳. روابط بین جداول

- هر پروژه به یک کارفرما تعلق دارد.
- هر پیشنهاد همکاری به یک فریلنسر و یک پروژه مرتبط است.
- هر فریلنسر برای هر پروژه حداکثر یک پیشنهاد می‌تواند ثبت کند.
- هر پروژه می‌تواند چند پیشنهاد داشته باشد، اما فقط یک پیشنهاد می‌تواند پذیرفته شود.
- هر کاربر می‌تواند اطلاعات پروفایل حرفه‌ای، مهارت‌ها، نمونه‌کارها و گواهینامه‌های خود را داشته باشد.
- هر پروژه می‌تواند به چند دسته‌بندی و چند مهارت موردنیاز مرتبط باشد.
- جدول `AdminAccounts` برای شناسایی کاربران دارای دسترسی مدیریت استفاده می‌شود.

برای برقراری ارتباط بین جداول و حفظ صحت اطلاعات، از کلیدهای اصلی (Primary Key)، کلیدهای خارجی (Foreign Key)، محدودیت‌های یکتایی، محدودیت‌های بررسی داده و مقادیر پیش‌فرض استفاده شده است.

## ۴. قوانین و محدودیت‌های پایگاه داده

قوانین زیر در پایگاه داده پیاده‌سازی شده‌اند:

- ایمیل و کد ملی کاربران باید یکتا باشند.
- کد ملی باید شامل ۱۰ رقم باشد.
- شماره تلفن اختیاری است؛ در صورت ثبت، باید با قالب تعریف‌شده برای شماره موبایل ایران مطابقت داشته باشد و تکراری نباشد.
- بودجه پروژه و پیشنهاد همکاری باید بیشتر از صفر باشد.
- عنوان و توضیحات پروژه نباید خالی باشند.
- مدت‌زمان تخمینی انجام پیشنهاد باید بیشتر از صفر باشد.
- فقط پروژه‌های باز امکان دریافت پیشنهاد دارند.
- کاربران نمی‌توانند برای پروژه‌های خودشان پیشنهاد ثبت کنند.
- حساب‌های مدیر اجازه ثبت پروژه یا پیشنهاد همکاری ندارند.
- برای هر پروژه حداکثر یک پیشنهاد پذیرفته‌شده مجاز است.
- وضعیت پروژه‌ها و پیشنهادها باید از بین مقادیر مجاز تعریف‌شده انتخاب شود.

برای اجرای برخی از این قوانین، از تریگرها (Triggers) استفاده شده است.

## ۵. داده‌های آزمایشی

برای بررسی عملکرد پایگاه داده، اطلاعات آزمایشی زیر ثبت شده است:

- ۴ کاربر، شامل یک مدیر سیستم
- ۳ پروژه
- ۴ پیشنهاد همکاری
- ۳ دسته‌بندی
- ۵ مهارت
- اطلاعات نمونه برای پروفایل‌های حرفه‌ای، مهارت‌های کاربران، دسته‌بندی و مهارت پروژه‌ها، نمونه‌کارها و گواهینامه‌ها

این اطلاعات امکان بررسی روابط بین کارفرماها، فریلنسرها، پروژه‌ها و پیشنهادهای همکاری را فراهم می‌کنند.

**نکته امنیتی:** مقادیر مربوط به `PasswordHash` در داده‌های آزمایشی صرفاً مقادیر نمایشی هستند و هش امن رمز عبور محسوب نمی‌شوند. این مقادیر برای احراز هویت واقعی مناسب نیستند.

## ۶. پرس‌وجوها و آزمون‌های انجام‌شده

چهار پرس‌وجوی اصلی برای بررسی اطلاعات پایگاه داده اجرا شده‌اند:

۱. نمایش پروژه‌های باز به همراه دسته‌بندی و نام کارفرما.

۲. نمایش پیشنهادهای ثبت‌شده برای یک پروژه مشخص.

۳. محاسبه تعداد پروژه‌ها و پیشنهادهای هر کاربر.

۴. نمایش مهارت‌های موردنیاز هر پروژه.

همچنین پنج آزمون برای بررسی محدودیت‌های پایگاه داده انجام شده است:

۱. تلاش برای ثبت ایمیل تکراری.

۲. تلاش برای ثبت کلید خارجی نامعتبر.

۳. تلاش برای ثبت پیشنهاد تکراری برای یک پروژه توسط یک فریلنسر.

۴. تلاش برای ثبت پروژه با بودجه صفر.

۵. تلاش برای پذیرفتن بیش از یک پیشنهاد برای یک پروژه.

هر پنج آزمون نامعتبر با موفقیت توسط محدودیت‌ها و قوانین پایگاه داده رد شده‌اند.

۱. نرم‌افزار SQL Server Management Studio را اجرا کنید.

۲. به یک نمونه از SQL Server متصل شوید.

۳. فایل `freelancer_database.sql` را باز کنید.

۴. اسکریپت را بررسی و در محیط مناسب SQL Server اجرا کنید.

**توجه:** اسکریپت موجود با زبان T-SQL و مخصوص Microsoft SQL Server تهیه شده است و بدون تبدیل، مستقیماً در PostgreSQL قابل اجرا نیست.
